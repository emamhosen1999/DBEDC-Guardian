## How the bridge works

Cyber is a design language like the dormant ones in `resources/css/design/` (see `_contract.css`):
`<html data-design="cyber">` switches it on and it is the default for everyone (`RadixThemeContext.jsx`,
with a one-time move of settings saved on stock Radix; the pre-paint script in `app.blade.php` mirrors it).
Pages never reference Cyber directly. They keep using Radix components, `var(--gray-a11)`,
`color="green"`, `<Panel>` … and inherit Cyber through three token layers:

1. **`resources/css/design/cyber/palette.css`** (generated by `scripts/design/cyber-palette.mjs`) re-points
   Radix's raw colour scales. Every Radix hue maps to a Cyber hue, so `--red-9`, `color="amber"`,
   chart series and badges all land on the Cyber palette. The script checks WCAG contrast and fails on
   regressions — edit the script, never the CSS.
2. **`cyber/tokens.css`** maps Cyber values onto Radix variables (type ramp, spacers, radii, surfaces,
   shadows, focus) and onto the app layer (`--dl-*` from `_contract.css`, mobile-aligned `--aero-*`).
3. **`cyber/components.css`** skins Radix components where a token cannot express Cyber (square corners on
   pills, uppercase micro-type, outline buttons, glass menus/dialogs, the dense `.table`).
   **`cyber/shell.css`** holds the app shell and the shared surfaces (`.dl-card`, `.dl-hud-line`,
   `.dl-page-head`, `.dl-chip`, `.dl-row`/`.dl-col`, `.dl-section-label`, `.dl-list`, `.dl-auth*`, `.dl-error*`).

Dark is the faithful Cyber palette. **Cyber Light** is derived (the kit ships dark only): same structure,
light cool canvas, darkened azure for AA contrast, Radix's own AA-tuned light hues.

### Rules for batches 2–5

1. Map, don't restyle. Prefer Radix props and tokens; do not hard-code hex/rgb colours, `fontFamily`
   ('Space Grotesk', 'Inter') or numeric `borderRadius` in pages. For surfaces use `<Panel>`, `CommandCard`
   or `.dl-card`; for an unavoidable inline radius use `var(--dl-panel-radius, Npx)` (or `R(N)` from the
   dashboard kit) so Cyber can square it.
2. Every shell page starts with `<PageHeader>` (one h1); sections are `.dl-section-label` rows or card headers;
   content sits in `.dl-row`/`.dl-col` with no gutters.
3. Secondary text uses `color="gray"` / `var(--gray-11)`. Never dim text with `opacity` below .62 (AA).
4. Primary action = solid button, secondary = `variant="outline"`, neutral = `variant="outline" color="gray"`.
5. Every migrated page is captured at 1440x900 and 390x844 in dark and light, paired with the closest live
   Cyber page, and its computed-style mismatches recorded before it moves to **verified**.
6. Keep behaviour, permission gates and data flow identical; UI copy says "Employee", never "User".
